# 子網站管理者權限設計

## 目的

將全域角色 `editor` 的顯示名稱改為「子網站管理者」，讓管理員指定一個子網站後，該使用者可以登入後台並完整管理該子網站，但不能進入其他子網站或全域管理功能。

## 已確認的行為

- `admin` 維持「管理員」，可登入後台並管理所有子網站及全域功能。
- `editor` 的程式值保留不變，顯示名稱改為「子網站管理者」。
- 子網站管理者建立或編輯時必須指定一個子網站。
- 子網站管理者的 `SiteUser.role` 固定寫入 `admin`，取得該子網站完整站內權限。
- 子網站管理者登入 `/admin/login` 後直接進入指定子網站儀表板。
- 子網站管理者不可查看其他子網站，也不可使用全域儀表板、子網站管理、使用者管理或功能選單。
- 以上限制必須由伺服器端驗證，不能只依賴隱藏導覽連結。
- 不新增資料庫欄位，沿用 `User.role`、`User.allSites` 與 `SiteUser`。

## 相容性決定

新的使用者表單不再提供「不設限（所有子網站）」選項。既有 `allSites=true` 的 `editor` 帳號不再取得不設限授權；全域管理員必須重新編輯該帳號並指定子網站後，該帳號才能登入後台。既有 `allSites` 欄位保留，避免不必要的資料庫 migration。

## 非目標

- 不新增第三種全域角色。
- 不改變前台會員登入與前台內容可見性的規則。
- 不讓子網站管理者使用全域使用者管理或建立、刪除子網站。
